Fix Dependabot issues

Create /fix-dbot-issues with the operator’s exact description and install the complete skill on both workers listed in the authoritative inventory.

Expected behavior

StageOutcome
ScopeUse an explicit repository list when provided; otherwise enumerate every repository in the named organization with complete pagination. Resolve an ambiguous organization before scanning.
Inspect and fixCheck open Dependabot security alerts and update PRs, deduplicate overlapping work, attempt compatible fixes, regenerate lockfiles, and run relevant repository checks.
ReviewOne consolidated PR per repository with viable fixes, including alert/update references, validation, and unresolved counts. Leave merging to the operator.
ReportShow repositories with PR links and unresolved counts, then repositories verified to have no issues. Account separately for blocked scans and repositories with issues but no viable PR.

Implementation and verification

  1. Add the canonical skill, discovery metadata, worker catalog entry, and repository routing/documentation.
  2. Validate the skill frontmatter and instructions; preserve existing uncommitted work.
  3. Transfer only skill assets to the verified worker accounts, stage before installation, and verify source-matching hashes.
  4. Check Codex skill discovery on each worker and record the observed destination, digests, and limitations in its machine record.

Installation is authorized by this request. It does not run an organization scan or activate fleet assignments. Ubuntu authentication uses a disposable T3 private password prompt; Windows uses the existing local SSH identity.

Clarifications

No product requirements need clarification. At invocation, the skill asks for the organization only if the assignment does not identify one unambiguously.
