Nebula Command · implementation plan · 27 October 2026

Use credentials without putting them in agent context

Keep encrypted credentials in the repo. Require the operator to submit a private age identity through T3 Code for each operation.

1 · OperatorSupplies the key through request_secret with private-file delivery.
2 · Local helperReads the private file, uses age, and removes the submitted copy on success or failure.
3 · AgentReceives an allowlisted status result. No key, password, session token, plaintext output file, or arbitrary consumer command.

Implementation

  1. Add an encrypted credential catalog for the Windows server KVM, without real credentials or a permanent decryption key.
  2. Add commands to seal a privately supplied password, verify decryption, and perform a bounded KVM authentication check followed by logout.
  3. Keep the key and decrypted payload inside local processes. Suppress subprocess and device error bodies. Require verified HTTPS and refuse redirects.
  4. Document operator key generation/backup, the exact T3 prompt workflow, cleanup, rotation, and the distinction between a supplied temporary copy and a recovery key.
  5. Add a commander skill and behavioral tests covering real age round trips, incorrect keys, malformed payloads, input cleanup, output redaction, and bounded KVM login/check/logout.

Trust boundary

This prevents routine disclosure to the model and tool transcript. It is not isolation from an unrestricted agent or administrator on the same account: those processes could read the private staging file or memory, replace the helper, or invoke decryption themselves. Strong enforcement would require a separately protected service/tool accepting an opaque secret reference.

Validation and activation

Implemented and validated: all 34 tests pass, including real age encryption/decryption with disposable keys and simulated KVM authentication responses. The commander skill passes its validator, local documentation links resolve, and inventory validation passes. No real credential, key, or KVM session was collected or created.

Real enrollment requires the operator's public recipient and a private password submission; private keys remain operator-held between operations. The live KVM's firmware/API compatibility and TLS trust remain to be verified.
